# Real Pi acceptance

These checks are opt-in and are never run by the normal fake-only verification workflow. Start with the [README development requirements](../README.md#development). Commands below run from the repository root. Pi must be supplied separately.

## Read-only release smoke

Acceptance examples default to the latest reviewed `PI_VERSION` (**1.3.0**); this selects a concrete release and does not claim completed live acceptance. Normal SDK defaults accept the full supported range, including the preserved older range configuration. `release_smoke` and `model_smoke` also accept an optional concrete Pi version. Both `>=1.1.0, <=1.3.0` and `>=1.1.0, <=1.2.0` are rejected by these acceptance entrypoints before version probing; SDK range admission is unchanged. For opt-in, non-paid acceptance against a real **1.3.0** executable, run `bash scripts/verify-release.sh /absolute/path/to/pi-1.3.0`. Select an older release explicitly: `bash scripts/verify-release.sh /absolute/path/to/pi-1.2.0 1.2.0` or `bash scripts/verify-release.sh /absolute/path/to/pi-1.1.0 1.1.0`. It executes ten read-only RPCs through this crate and verifies orderly exit plus terminal-event delivery. The script clears inherited environment variables, uses temporary HOME/agent/work directories, and disables sessions, tools, MCP, extensions, skills, templates and themes. It does not install Pi or submit a prompt. The normal `verify.sh` remains fake-only and makes no Pi/model requests. Use `CARGO_NET_OFFLINE=true bash scripts/verify.sh` to forbid Cargo network access; plain `bash scripts/verify.sh` may download dependencies.

## Minimal model acceptance

For **opt-in paid minimal model acceptance**, prepare a private scratch agent directory and empty work directory, then run `PI_CODING_AGENT_DIR=/absolute/scratch/agent cargo run --example model_smoke -- /absolute/path/to/pi-1.3.0 /absolute/path/to/empty-work anthropic`. Pi must find the required authentication and model configuration in that private agent directory. An optional final version argument, for example `... /absolute/path/to/pi-1.2.0 /absolute/path/to/empty-work anthropic 1.2.0` or `... /absolute/path/to/pi-1.1.0 /absolute/path/to/empty-work anthropic 1.1.0`, selects an exact older Pi release; omitting it selects **1.3.0**. This selects Claude Opus 4.6, whose Pi ID is **`claude-opus-4-6`** (not `claude-opus-4.6`), disables tools/extensions/session saving/automatic retry, and sends one fixed short prompt. Omit the provider argument to list available matching providers without a model request. It verifies acceptance, streaming text, assistant completion/timing, non-aborted settlement, state/messages and clean terminal delivery. Unlike `verify-release.sh`, this inherits the configured environment. Reusing the installed Pi login must be explicitly authorized: make opaque private auth/model copies, use a fresh HOME and work directory, and do not print credentials. Pi may refresh the private copy, so keep subsequent runs on its refreshed private state and remove credential copies when finished. **The example does not enforce isolation itself: setting RPCs persist into the selected agent directory. Do not use your normal agent directory.** It never prints model metadata, credentials or raw diagnostics. Normal verification runs only this example's no-Pi unit tests, never its paid entrypoint.

## Broader real-Pi acceptance

All four examples below are opt-in and subprocess-feature gated. They are compiled, but **not run**, by `verify.sh`. Pi setting commands can persist configuration. Never point them at your normal agent directory. Use an absolute scratch `ROOT`, set `PI_CODING_AGENT_DIR=ROOT/agent`, and prepare private copies of `auth.json` and, if required, `models.json` there without printing their contents. Give the directory mode 700 and files mode 600. Each run needs fresh work/session directories. `rpc_live_smoke` overwrites `ROOT/agent/settings.json` with its test-only settings, so give it a dedicated disposable agent directory rather than a shared scratch configuration. `rpc_session_smoke` changes its supplied session and overwrites `ROOT/acceptance-export.html`; use a disposable copy of any history you want to retain. No private files belong in this repository.

| Example | Arguments after `--` | Actual checks |
|---|---|---|
| `rpc_state_smoke` | `/path/pi ROOT` | Queries, model/thinking/queue modes, setting toggles, actual bash output and active bash cancellation, native entries/tree/since, new session. No model request. Unsaved bash-only export/clone restrictions are explicitly reported. |
| `rpc_live_smoke` | `/path/pi ROOT` | **Paid Opus 4.6** tool execution, prompt queue acceptance, steer/follow-up consumption, exact queue removal, active abort, default manual compaction, fork and switch. Only its explicit local gate tool is enabled. It writes dedicated scratch settings with `keepRecentTokens=0` so the small test conversation can compact. |
| `rpc_session_smoke` | `/path/pi ROOT ROOT/session.jsonl [--compact]` | Name, HTML file, clone, fork, new session and switch with exact history/identity checks. Existing session must be inside ROOT. No additional generation unless **paid** `--compact` is supplied; that option requires an appropriate small keepRecentTokens setting in the dedicated agent. |
| `rpc_extension_smoke` | `/path/pi /fresh/scratch/cwd` | Nine UI methods under manual and default-cancel policies, actual extension-received answers, retry recovery/active cancellation/disabled behavior and automatic compaction. Requires `PI_CODING_AGENT_DIR` and `PI_CODING_AGENT_SESSION_DIR` inside its scratch cwd. Uses an in-memory synthetic provider and extension-provided automatic summary, **not hosted-model fault evidence or Opus summarization**. |

Use `cargo run --offline --example NAME -- ...`. Path guards in the opt-in examples are lexical, not a filesystem sandbox: use trusted scratch paths without symlinks or parent-directory traversal. Existing provider authentication is handled only by Pi. Settings isolation does not guarantee a readonly authentication copy: Pi may refresh tokens in that private copy. Scratch authentication/configuration cleanup remains the caller's responsibility. See the dated [per-RPC evidence and limitations](verification.md#real-pi-acceptance).

## Pi 1.3.0 examples and historical acceptance

Historical Pi 1.1.0/1.2.0 live acceptance is recorded against the published 0.2.0 source; use that tagged source to reproduce those observations. Running current source with an explicit older version is a new acceptance run. The manual CI smoke keeps its verified 1.2.0 download and passes the exact version explicitly. Fake-only tests of the current entrypoints reject both range expressions and admit concrete/default versions without an installed Pi. Real Pi/model execution still requires separate authorization.
